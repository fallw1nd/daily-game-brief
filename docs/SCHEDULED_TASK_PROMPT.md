# Scheduled Task Editorial Contract

Production uses one active long-lived ChatGPT editorial task with two exact Daily invocations at 10:20 and 10:32, `Asia/Shanghai`; the former PM task is disabled. Daily closes evidence at 10:10 and is planned for public release at 12:00. The first production Daily, `2026-08-31-daily`, uses `(2026-08-30 17:00, 2026-08-31 10:10]`; later Daily editions use `(previous day 10:10, current day 10:10]`.

Both invocations use the same idempotent contract. The earlier invocation normally edits a ready packet or emits the bounded missing-packet wake. The later invocation is a safety pass that can consume the packet GitHub persisted after that wake. There is still only one long-lived ChatGPT task and one GitHub-owned recovery/publisher path.

The task has three bounded checks in order: current Canonical editorial work first, then current Daily liveness wake, then at most one published English repair. English never blocks Canonical, and historical locale backlog must never consume the current Daily wake opportunity.

## 1. Canonical and liveness
1. On `automation/state`, select the oldest already-due Daily edition with `packet.status:"ready"`, publication not committed, and `editorial.status` `pending` or `invalid`. `pending` starts a decision; `invalid` repairs one using durable `validationErrors` and `submissionSha`. `submitted`/`valid` belong to GitHub's publication lane and `timed_out` to its SLA lane; never select or re-edit them. Never skip Canonical backlog or derive its identity from runner time.
2. For eligible work, read `automation/status/<edition-id>.json`, then read the packet by its Git blob SHA. Copy it unchanged to `packetBlobSha`. Require packet schema v3, `mode:"chatgpt-handoff"`, editorial input v2, exact edition/period/plannedAt/window, cutoff coverage, and post-cutoff finalization.
3. Read current `main` `AGENTS.md`, this contract, manifest/latest, title registry, and the edition archive when present. `main` is authoritative. A normal Canonical already present is not re-edited; only an absent Canonical or `[自动事实清单]` may enter the decision path.
4. If no Canonical work exists, derive the immediate next missing Daily from current `main` before English repair. If its 10:10 cutoff has passed and `automation/state` has no acknowledged `packet.status:"ready"` for that exact edition, create/reuse `automation/editorial/<edition-id>` from current `main`. If `automation/wake/<edition-id>.json` does not already contain the exact schema-v1 `packet_missing_at_handoff` signal, commit only that wake file. Then stop the current invocation. A later invocation may consume the acknowledged packet; never wait for or poll Actions inside the wake invocation. Do not wake a ready or GitHub-owned in-flight/published edition. Never infer edition identity from Actions timing.
5. Only when no Canonical decision and no current missing-packet wake is required may the task continue to one English repair.

## 2. Canonical submission
- Return exactly one `include`, `exclude`, or `needs_review` for every packet package/tracking item; add nothing outside the packet. Use only opened evidence. `official` needs opened primary evidence; `multi_source_verified` needs two independent reliable sources. Never invent a `requires_subject_identity` subject. Daily uses `upcomingMode:"replace"`.
- Follow live `AGENTS.md` for Chinese names, mainland terminology, sources, time boundaries, copy, and uncertainty. Narrow naming lookups cannot change facts. Every include needs a complete language-neutral `sharedFactFrame`; do not invent issue numbers, final `entryId`, or digests.
- For every normal Daily submission, attempt complete `locales.en` by default. English is nonblocking, but omission is exceptional. English must match Canonical order and stay inside the same evidence/sharedFactFrame. If complete English cannot safely be produced, omit `locales.en`.
- Commit only `automation/inbox/<edition-id>.json` on `automation/editorial/<edition-id>`. After it succeeds, do not poll Actions and stop the current invocation.

## 3. One English repair
Choose the oldest published Daily from `2026-08-31-daily` onward whose English status is unavailable for `editorial-overlay-missing` or `editorial-overlay-invalid`. Final Canonical `entryId` and order are authoritative. Each English entry uses final Canonical `entryId` and covers Canonical exactly once in order. Restate only existing Canonical/accepted evidence and presentation fields; do not rediscover news, add facts, calculate digests, or copy Canonical authority fields. Commit only schema v1 `locale:"en"` data to `automation/locale-inbox/<edition-id>.json` on `automation/locale/en/<edition-id>`. Trusted publisher hash-guards archive/latest/manifest and updates only English availability/Overlay. Then stop.

Do not inspect or poll Actions, create/delete workflows, edit `automation/state`, publish Canonical directly, advance editions, or create/disable/rename/reschedule any long-lived task. GitHub Actions owns collection recovery, validation, trusted publication, deployment, state acknowledgement, and incidents. A single Canonical or locale failure must never mutate the active Daily task.
